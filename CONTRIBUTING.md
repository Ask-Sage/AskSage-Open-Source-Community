# Contributing Guidelines

Pull requests, bug reports, and all other forms of contribution are welcomed and highly encouraged! 🎉

## Code of Conduct

Please review our [Code of Conduct](CODE_OF_CONDUCT.md). We expect all contributors to follow it.

## How to Contribute

### Reporting Issues

- **Search first** — Check if the issue already exists before opening a new one.
- **Be specific** — Include steps to reproduce, expected vs. actual behavior, and any relevant error messages.
- **Security issues** — Do **not** file public issues for security vulnerabilities. See [SECURITY.md](SECURITY.md).

### Submitting Pull Requests

1. **Fork** the repository
2. **Create a branch** from `main` (e.g., `feature/my-improvement` or `fix/bug-description`)
3. **Make your changes** — Keep PRs focused on a single change
4. **Test your changes** — Make sure examples run correctly
5. **Submit a pull request** — Describe what you changed and why

### Guidelines

- Follow the existing coding style and conventions
- Update documentation if your changes affect it
- Keep commits clear and descriptive
- One PR per feature or fix

## Ideas for Contributions

- New example notebooks demonstrating Ask Sage API features
- Improvements to existing examples
- Documentation fixes and clarifications
- Bug fixes
